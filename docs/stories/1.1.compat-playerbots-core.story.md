# Story 1.1: Compat with playerbots AzerothCore

Status: InProgress

## Story

As an Araxia operator  
I want `mod-auctionator` to build and run against `araxiaonline/azerothcore-wotlk-mod-playerbots` (Playerbot branch)  
so that auction bots can ship in the araxia-core Docker stack alongside playerbots.

## Acceptance Criteria

1. Module compiles as a static AC module against current playerbots-integrated core (no cmake/ninja errors).
2. `EventMap::ScheduleEvent` calls use `std::chrono` durations (`Milliseconds`), matching current AC API.
3. `WorldSession` construction includes the `accountFlags` argument required by current `WorldSession` ctor.
4. Auctionator’s fake session is heap-owned for the process lifetime (no dangling stack pointer used by `CreateAuction`).
5. Module can be enabled in `araxia-core` (`config/modules.yml`) and included in a successful `make build`.
6. Story file lives under `docs/stories/` following BMAD story conventions.

## Dev Notes

### Context

Araxia is moving from NPCBots-based cores to the **playerbots** fork:

- Core: `araxiaonline/azerothcore-wotlk-mod-playerbots` (`Playerbot` branch)
- Orchestration: `araxia-core` Docker/Makefile stack

`araxia-main` / older module checkouts failed Docker builds with:

1. `EventMap::ScheduleEvent` — second arg is `Milliseconds`, not raw `uint32`
2. `WorldSession` ctor — inserted `uint32 accountFlags` before the socket arg

`origin/main` already contains chrono-based `ScheduleEvent` and an `accountFlags` literal `0`, but still assigns `session = &_session` where `_session` is a **stack** temporary in `Initialize()`. `CreateAuction()` later does `Player player(session)`, which is use-after-scope.

### Target APIs (playerbots core)

```cpp
WorldSession(uint32 id, std::string&& name, uint32 accountFlags,
             std::shared_ptr<WorldSocket> sock, AccountTypes sec, ...);

void EventMap::ScheduleEvent(EventId eventId, Milliseconds time, ...);
```
